## Intake items

### 1.3-I01: Escrow yield strategy extension (proposed)
- **Source:** djat_x_burin discussion thread `#pathways-insurance-yield`
- **Summary:** §4.9 extension proposing a `yield_routing_strategy` field that allows
  sponsors to direct yield toward specific outcomes (reinvest, donate to climate
  pools, distribute as membership dividends).
- **irl.coop relevance:** Directly affects the yield vault mechanism described in
  `pathways-integration.md` §3. Could inform the `Insurance.Yield.Settle` template
  mapping.
- **Status:** Proposed upstream. Not accepted into 1.3 draft yet.
- **irl.coop action:** Monitor. Do not implement until 1.3 is frozen.

### 1.3-I02: Phase declaration auto-propagation (proposed)
- **Source:** RIS §4.8.9 revision proposal
- **Summary:** When a sub-pathway is forked from a parent, the child's phase
  declarations inherit from the parent's active phase unless explicitly overridden.
- **irl.coop relevance:** Would simplify the `Peer.Template.Fetch.A3` template's
  phase handling in the intent-mapping YAML.
- **Status:** Under discussion in RIS §4.9 draft.
- **irl.coop action:** Track. Update `pathways-intent-mapping.yaml` when frozen.

### 1.3-I03: Sponsor commitment attestation bundle (new)
- **Source:** Appendix C meta-pathway discussion
- **Summary:** Sponsor commitments (§4.9) should be wrapped in an Aqua attestation
  bundle that includes the sponsor's own trust key, creating a verifiable chain
  from the sponsor's historical run data.
- **irl.coop relevance:** Would strengthen the `Insurance.Sponsor.Commitment.v1`
  schema in the intent-mapping YAML. The attestation would allow the Safe contract
  to verify sponsor historical data offline.
- **Status:** Draft proposal in `djat_x_pathways/revisions/1.3/proposals/`.
- **irl.coop action:** Track. Schema should evolve to include `attestation_bundle`
  when 1.3 is frozen.

### 1.3-I04: Non-delegable acts registry (new)
- **Source:** `non_delegable_acts` field in gate_profile (§4.8.4), proposed expansion
- **Summary:** A registry-level `non_delegable_acts` list that can be referenced by
  template identity triple, so governance bodies can tag certain acts as non-delegable
  for entire domains.
- **irl.coop relevance:** Maps to the Safe threshold model — certain acts (e.g.,
  `negotiate_bind`, `certify`) should always require human approval regardless of
  autonomy band.
- **Status:** Proposed. Not yet in draft spec.
- **irl.coop action:** Track. Would update the gate_profile mappings in the
  intent-mapping YAML.
