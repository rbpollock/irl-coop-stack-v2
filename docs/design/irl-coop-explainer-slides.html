01 / 10A sovereign cooperative network
EXPLAINER · GRAPH FRAMING
Every account a Safe.
Every relationship a typed edge.
One graph, four layers.
irl.coop is a peer-to-peer cooperative economy: time-banking, barter, shared infrastructure, joint ventures — governed by its own members through software, not intermediaries.
This deck presents the system as a network: nodes, layers, thresholds, flows — and ends with the questions we need a network theorist to stress-test.
02 / 10The graph IS the system
There is no hidden state. The system is a graph, and the graph is the system — nodes, edges, and weights are all on-chain or registry-anchored.
Nodes = Safes — universal accounts: person (1-of-1) · group (N-of-M) · DAO. Every actor is a node.
Edges = relationships — ownership (membership) plus declared typed relationships with terms.
Rule: ownership implies membership ONLY. Every other meaning is declared on the edge record, never inferred.
No unowned objects: every resource is an asset of some Safe — context resolution depends on a complete object graph.

03 / 10A multiplex network — four edge layers
Relationships are multiplex: four orthogonal edge layers on the same node set.
governancewho controls — owner seats, thresholds, reserved powers
infrastructurewhat's shared — namespace, mailboxes, quotas
trustinteroperation — OIDC · SMTP · Matrix · arbitration
economicsvalue flow — credit ledgers, funding, sponsorship
Relationship types are layer combinations:
member-of = governance · subgroup-of = governance + infrastructure
federated-with = trust · sponsored-by = economics
04 / 10Thresholds — hyperedges & nested authority
Control is distributed by construction: no owner acts alone, and authority composes across nesting.
N-of-M owner set = weighted hyperedge. A quorum of the set is required to act; the threshold is the edge weight.
Nesting: a Safe can sit in another's owner set. The Board Safe (3-of-5 directors) contributes its EIP-1271 signature to the department's 2-of-3 — authority composes hierarchically.
Guards enforce edge terms — reserved powers, spending limits, seat protection — as code, not discretion.
Timelocks make sensitive changes reversible (circuit breakers); one compromised seat cannot cause permanent damage.
05 / 10Two topologies from one primitive set
The same nodes, layers, and thresholds express opposite network shapes — no new machinery.
co-opFlat: membership IS the owner-set; dense, overlapping cliques; autonomous subgroups share the parent's namespace; federation seats in higher bodies.
nonprofitNested hub-spoke: board co-owns departments via declared edges with reserved powers; staff nested in departments; donors/sponsors as leaf edges.
Open question for review: which emergent properties differ between the shapes — resilience to node loss, information flow, tie strength, power-law behavior?
06 / 10Overlapping communities, no "hat-switching"
One identity, many memberships. The UI is a single world; the graph resolves authority.
Membership is a set, not a tree — a node belongs to many communities at once (your co-op, the coalition, the working group, the tractor-share).
Context is derived from the action: the edge being traversed determines the governing Safe. No mode-switching, ever.
Multi-parent is ordinary: "child of two groups" is just membership in two Safes, with thresholds defining how the seats combine.
Unified surface: one approval inbox across all memberships; permissions derived from seats; the confirmation line IS the context ("as member of Cold Storage Co-op — 2-of-3").
07 / 10Value & information flow on the edges
The economy runs ON the graph: flows are edge properties, settled and verifiable.
Ledgers live on edges: relationship-scoped mutual credit — labor swaps, time banks, equipment shares. Double-entry, instant settlement, visible state ("Maria +4h · Jose −4h").
Provenance: data stays at the node; hashes anchor on-chain — immutable edge history any node can verify (soil records, cold-chain logs).
zk-badges: prove a node property — degree ≥ 10, tenure ≥ 1 yr, contribution ≥ threshold — WITHOUT revealing the graph. Private attributes, public gates.
Hard rule: money stays auditable. ZK covers participation, never cash flows.
08 / 10Resilience & failure modes
The network is designed for its failure modes — abandonment, theft, lockout, splits.
Pre-commitment: constitutions are fixed at formation; they change only through the guarded path (a node cannot silently rewrite its edges).
Time is the resolution primitive: dead-man's switches escalate abandonment; timelocks make changes reversible; no threshold ever decays.
Arbitration: disputes over edge terms are first-class, on-chain, arbitrable — edges are contracts, not vibes.
Failure modes named: lockout (lost keys) · theft (compromised node) · regulatory overlay · colluding operators. Stance: no single point of failure by construction; thresholds define collusion.
09 / 10Open questions for network-theory review
1
Nested thresholds & cascades
A compromised high-degree node (board seat) propagates to every department it co-owns. Where do cascading failures emerge, and what redundancy structure is minimal?
2
Multiplex edge correlation
Governance + infrastructure + trust + economics on the same pair — is that reinforcing (sticky ties) or over-embedding (fragile)? What does balance theory say about signed layers?
3
Overlapping communities without hats
What does context-from-action do to brokerage and structural holes, compared with explicit workspace switching?
4
Time-bounded credentials (badge decay)
Decaying zk-badges as participation proof — how does expiration change trust diffusion vs. permanent reputation?
5
Anti-Sybil floor
What is the minimal participation requirement that resists Sybil without gatekeeping newcomers?
6
Small worlds
Will trust edges self-organize into small worlds? Should we engineer shortcuts and bridge roles deliberately?
